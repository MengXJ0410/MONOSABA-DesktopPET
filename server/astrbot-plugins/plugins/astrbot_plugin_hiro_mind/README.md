# 希罗酱の读心（astrbot_plugin_hiro_mind）

把「模型在写出回复之前，实际生成的那段思考」留下来，给管理员看。

用途只有一个：**查她为什么误解你**——她回之前，把你说的话理解成了什么。

## 为什么看不到历史里的思考

模型每轮确实在思考，AstrBot 也会把 `reasoning_content` 拼进当轮回复、作为 `think`
段写进历史。但 `plugin-immersion` 会在**下一次请求前**把历史里的 `think` 剥掉，
而 AstrBot 每轮保存历史时，用的正是「剥过的那一份」再追加新回复。

结果是：数据库里永远只剩最后一轮的思考，再往前的都被覆盖掉了。
线上 184 条 assistant 消息只看到 1 条 `think`，就是这个原因——不是模型没思考。

所以本插件不读历史，而是在 `on_llm_response` 当场留一份副本。

另外仍包了一层 `ProviderOpenAIOfficial._query_stream` 作为兜底：万一某个网关或
版本没有把思考回填到最终 completion，就从流式 chunk 里累积，挂到
`_hiro_mind_reasoning` 属性上。**不写回 `reasoning_content`**，所以不会污染
对话历史，也不会让她把自己的思考当上下文回读；补丁失败只打一条警告。

## 指令

| 指令 | 作用 |
|---|---|
| `/读心` | 最近 3 轮 |
| `/读心 8` | 最近 8 轮 |
| `/读心 40` | 上限 32，按 32 显示 |
| `/读心 清空` | 清掉当前会话的记录 |

只有管理员能用，且只在私聊生效（群里会拒绝，避免思维链外泄）。

## 输出格式

（下面是格式示意，内容为虚构，不是真实记录）

```
【后台草稿 · 最近 2 轮】
[1/2] 11-17 01:38
你：(身体的疲惫与强烈的困意，没一会儿便入睡了)
草稿：（总算睡下了。……呼。再回一句，我真要睁着眼睛到天亮了。）
她：（总算睡下了。）……呼。
```

- 每轮一条消息，只有单轮超过 900 字才会按换行切开；
- 超过 8 轮时，每轮展示量自动收窄（草稿 1600 → 800 字），避免一次刷几十条；
- `草稿` 是模型真实生成的中间文字，可能是英文、第三人称、带「应该怎么回」的口吻；
- 它不保证完整，也可能和实际回复不完全一致；
- 它只说明一件事：**她在动笔前锁定了哪个前提。**

## 输出被切成碎片怎么办

AstrBot 的分段回复默认对**所有结果**生效（`platform_settings.segmented_reply.only_llm_result`
为 `false`），会把命令输出也按 `。？！` 切成十几条、间隔随机 1.5–3.5 秒，读起来是碎的。

把那一项改成 `true` 即可：

- 她的回复是 LLM 结果 → 照样按句分段，聊天节奏不变；
- `/读心`、`/心情` 这类命令结果是普通消息 → 整块发出。

线上已改；如果哪天看到她回复变成一整条长消息，把这一项改回 `false` 即可恢复原样。

## 数据

- 每个会话保留最近 64 轮（可配），落盘 `plugin_data/astrbot_plugin_hiro_mind/mind.json`；
- 每条包含：时间、他说的话、她的回复、草稿（各截断存储）；
- 只记录装上之后的对话，之前的不可能补回来。

## 设计原则

- 不改回复内容、不改注入、不改历史；
- 补丁失败只打一条警告，不影响启动和聊天；
- 所有异常 fail-open，插件挂了不影响正常对话。
