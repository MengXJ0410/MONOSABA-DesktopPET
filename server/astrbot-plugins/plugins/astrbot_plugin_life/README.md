# 希罗酱的生活

让角色有自己的生活：每天生成生活事件，注入聊天上下文，偶尔主动私聊分享。

当前版本：`0.1.9`。

> **点评隔离**：事件带 `mood_skip_appraisal`（屏幕点评）时，`inject_life` 直接返回，不重置 `unanswered`、不更新 `last_user_at`。

> **会话范围**：生活事件、注入和 `/生活` 指令都只对 `target_umo`（默认主私聊）生效。群聊和其他私聊没有生活事件，`/生活` 会直接拒绝。`_status_text()`、`_affection_state()`、`_is_cold_war()` 也会二次校验 UMO，非主私聊一律返回拒绝/空值。

## 工作方式

1. 每天 06:30 用 GLM 生成 4–7 件当天事件，按早上/中午/下午/晚上/夜间分布。
2. 事件到点后变成“已发生”，并把情绪变化写进心情插件。
3. 每 20–40 分钟随机检查一次，按概率决定要不要主动私聊分享。
4. 私聊时通过 `on_llm_request` 注入“今天已经发生、他可能还不知道”的生活背景。
5. 日记插件读取同一批事件，作为「我的生活」的唯一事实来源。
6. 每晚 23:30 掷 5% 噩梦概率；触发后在 23:30–06:30 随机时间必定分享，不占日常额度。
7. 噩梦会拆成 3–6 段短消息，间隔 2–4 秒：先表达情绪（“我刚刚做噩梦了！”），再说这么晚还想说，然后简单说梦，最后可落地。

> 噩梦事件和当天生活事件写在同一个 `events/YYYY-MM-DD.jsonl` 里。
> 判断“今天是否已经播过种”只看非噩梦事件；凌晨出过噩梦的第二天仍会正常生成生活事件，重新生成时也会保留已有的噩梦记录。

## 噩梦与生活分享相互独立

- 噩梦的掷骰、预定、发送记录存在 `state.json` 的 `nightmares` 里，不写 `daily`。
- 噩梦不增加 `daily.shared`，不占当天生活分享配额。
- 噩梦不更新 `last_share_at` / `last_proactive_at` / `unanswered`，不会延长生活分享冷却或触发未回复升级。
- 生活分享的冷却、配额、未回复计数只由生活分享本身维护。
- 旧版 `daily` 里的 `nightmare_roll` / `nightmare_scheduled_at` 会在读取状态时自动迁移到 `nightmares`。

## 生活分享频率与好感度

| 好感 | 每天目标 |
|---|---|
| 0–10 | 0 条 |
| 10–50 | 1–3 条 |
| 50–100 | 3–6 条 |
| 100+ | 5–10 条 |

- 读不到好感（心情插件未加载、状态缺失）时**暂停主动分享**，不再退回固定的 3–5 条。
- 目标还会被当天事件数截断：只有 2 件可分享事件时，最多分享 2 条。
- 好感在当天中途变化时，当天已定的目标不会自动上调；下降超过档位时会按新档位收紧。
- `/生活 分享` 手动测试会计入当天配额和分享冷却，但不会增加未回复计数，也不会触发抱怨/冷战升级。

## 未回复升级与冷战

- 第 1 条分享没回 → 第 2 条分享后单独发 1–2 条抱怨，生气 +0.35。
- 第 2 条还没回 → 第 3 条分享后单独发 1–2 条更冷的话，生气锁到 0.92，进入冷战。
- 冷战期间暂停生活分享；噩梦和日记分享不受影响。
- 冷战状态由心情插件管理，跨天保留，直到用户主动安慰。
- `/生活 分享` 手动测试不会触发升级。

## 默认世界观

`world/hiro.md` 写给希罗和艾玛：魔女审判结束后，两人同住公寓、同班、一起上下学，是最亲近的人但没有越过那条线。换人格时改这个文件和配置里的 `persona_name` / `companion_name` / `user_alias` 即可，不用改代码。

主动分享/噩梦的「边界」会读取心情插件的好感状态：未进入伴侣线时保持暧昧但守界；进入伴侣线后允许承认依赖、想念和吃醋，艾玛则回到「最好的朋友」的位置。这样好感度不只影响主聊天，也影响她主动找你时的语气。

## 指令

仅管理员，且只在主私聊（`target_umo`）生效：

- `/生活`：查看今天的事件和分享状态。
- `/生活 生成`：补生成今天剩余时段的事件。
- `/生活 分享`：强制分享一件，测试用。
- `/生活 暂停` / `/生活 继续`：暂停/恢复主动分享；生成和注入继续。
- `/生活 噩梦`：强制触发一次噩梦，测试用。
- `/生活 清空 确认`：清空今天的事件。

## 数据

```text
data/plugin_data/astrbot_plugin_life/
├─ events/YYYY-MM-DD.jsonl
├─ backups/YYYY-MM-DD.jsonl
└─ state.json
```

事件按天存 JSONL，字段包括 `occurred_at`、`summary`、`detail`、`mood_delta`、`share.desire`、`privacy`、`status` 等。`privacy=secret` 的事件不会注入、不会分享，也不会进日记。

## 配置要点

- `target_umo`：只往这个会话注入和主动发送。
- `event_provider_id` / `share_provider_id`：事件用 GLM，分享文案用主模型。
- `share_min` / `share_max`：每天 3–5 条。
- `base_probability` / `cooldown_minutes` / `after_user_minutes`：默认 0.7 / 60 / 8。
- `unanswered_complain_after` / `unanswered_cold_war_after`：默认 1 / 2，对应第 2 条抱怨、第 3 条冷战。
- `unanswered_message_delay_min/max`：抱怨/冷战消息在分享后延迟 4–12 秒。
- `cold_war_enabled`：关闭后只抱怨，不会进入冷战。
- `force_one_if_none`：每天随机 18:00–22:30 的保底时间，到点还没分享就强制发一件。
- `nightmare_probability`：默认 0.05。
- `mood_link`：事件驱动心情，心情反过来影响分享概率和语气。
- `dry_run`：只写日志不发送，用于演练。
