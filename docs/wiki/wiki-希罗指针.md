希罗指针是桌宠的第二根光标：它不属于 Windows，也不抢真实鼠标。她可以自己把它移到屏幕上的任何地方，你平时看到的「闲时游走」只是它的待机状态。

## 为什么需要自己画

Windows 同一时刻只有一个系统光标。同时插两个鼠标，系统也只驱动同一个；`SetCursor` 换的是样式，不是新光标。没有「创建第二个系统光标」的公开接口。

所以第二指针由桌宠自己绘制：

- 每块显示器一个**全屏透明、置顶、鼠标穿透**的窗口，只画光标；
- 浮层是桌宠主窗口的 owned window，稳定压在人物上面；
- `skipTaskbar`、`focusable: false`、`hasShadow: false`，不抢焦点、不进任务栏、不挡点击；
- 主进程按虚拟桌面 DIP 坐标路由，只显示指针所在那块屏的浮层，其余隐藏。

一个容易踩的坑：Windows 在创建 / 显示 owned 浮层时，会把 owner 的 `WS_EX_TOPMOST` 清掉。表现是人物突然掉到浏览器后面，像「隐藏」了。所以「强制顶层」的 0.9 秒循环会先补 `setAlwaysOnTop` 再 `moveTop`，浮层创建 / 加载完 / 切换屏幕时也补一次。

## 皮肤与大小

内置 `.ani` 解析：RIFF → `LIST fram` → ICO → 8bpp / 24bpp / 32bpp BMP（调色板 + AND 掩码），得到 RGBA 帧、帧间隔和热点。希罗皮肤 `Normal.ani` 是 12 帧 32×32、约 12fps；不运行 `install.inf`，不改系统鼠标方案。

大小相对 Windows 默认光标（32 DIP），默认 **1.5×**，面板小窗可调 1.0–4.0×（0.5 步进）。放大用 `image-rendering: pixelated` 像素对齐，不发虚。

## 待机：闲时游走

没有 AI 动作时，指针复用原来的随机视线曲线（漂移 / 停顿 / 扫视），把「眼睛的目标」变成「屏幕上可见的光标」，再让眼睛去看这个光标。真实鼠标移动不再影响视线。

小窗里可以关掉「闲时随机移动」：指针停在最后一次位置（仍然可见、鼠标穿透），只等 AI 接管；人物闲时改用独立的随机视线自己看。重新开启时从当前位置重新起步，不会瞬移。

## AI 观察：她自己在看屏幕

开启希罗指针后（默认开），主进程 `pointer-ai.ts` 每 N 秒做一轮观察，默认 10 秒，面板可调 1–30 秒。

一轮的流程：

1. **选屏**：前台全屏 / 最大化窗口所在屏优先，否则鼠标所在屏（和随机点评同一套判断）。
2. **截图**：长边 768、JPEG 70 的压缩图，单轮超时 8 秒；聊天截图仍是 1280 / 85。
3. **指纹比对**：32×18 灰度指纹，只有变化超过约 8%（48/576 位）或换屏才继续。画面不动时 **0 次模型调用**，挂机不烧 token。
4. **调用模型**：`POST /pointer` 把截图交给桥接。桥接取当前人格 + 指针规则，带最近 6 条对话摘要，用 `text_chat` 直连调用——不经过 Agent，所以不写会话历史、不进长期记忆、不触发心情。
5. **下发动作**：模型只返回一个 JSON，主进程换算成屏幕坐标，通过 `pointer:control` 交给渲染层。

模型输出协议：

```json
{"act":"move","x":0.42,"y":0.66,"duration_ms":900,"hold_ms":1500,"reason":"去看他在写什么"}
```

```json
{"act":"none"}
```

- 坐标是相对截图的比例：左上角 `(0,0)`，右下角 `(1,1)`。桌面端再映射到该显示器的 DIP 边界，所以多屏、不同缩放都不会偏。
- 只移动，不点击、不拖拽、不滚轮。
- 非法 JSON、坐标越界、字段缺失一律按「不动」处理，绝不把指针甩出屏幕。
- `reason` 只写进日志，不上屏。

## 动作表现

- 从当前位置缓动到目标（smoothstep，`duration_ms` 由她决定），到达后停留 `hold_ms`。
- 停留结束交回闲时游走；如果落点在人物窗口外，指针会先滑回轨道再继续游走，不会瞬移。
- AI 动作和停留期间，Live2D 视线强制跟着指针。

## 开关与预算

- **一个总开关**：关掉指针 = 隐藏浮层 + 停止观察。它和随机点评彻底解绑，各自独立调度。
- 睡着时不观察：不截图、不调用模型。
- 每天最多 500 次模型调用，超了当天只保留本地游走。
- 同一时刻只跑一轮，定时器和「立即观察一次」不会叠加。

## 聊天端：她知道自己有指针

桌面消息带 `pointerEnabled` 时，桥接会通过临时 `TextPart` 注入一段能力提示（配置项 `pointer_hint`），告诉她：桌面上那个小光标就是她自己，可以移动但不能点击；如果用户在聊天里让她指某个东西，就答应并在下一次看屏幕时移过去。

这不会写进会话历史。聊天里提的要求会出现在下一轮观察带的「最近对话」摘要里，所以动作和对话是接得上的。

## 面板小窗

「真实交互 → 希罗指针」是一个独立开关（默认开），点击开关，悬停打开小窗：

- 总开关；
- 闲时随机移动；
- 大小滑杆（1.0–4.0×）；
- 观察间隔滑杆（1–30 秒，默认 10）；
- 状态行：今日调用次数、上次观察时间、跳过原因（画面没变 / 睡着了 / 今日调用已用完 / 截图失败 / 连不上 AstrBot / 她觉得不用动）；
- 「立即观察一次」。

设置写入 localStorage，重启保持。每次观察和动作都写 `userData/logs/pointer-ai.log`，排查时直接看这个文件。

## 已知边界

- 全屏独占游戏、UAC 安全桌面看不到指针。
- 虚拟桌面切换时，指针跟随当前桌面。
- 截图 / 随机点评会拍到指针本身。
- 屏幕长时间没有明显变化时她不会主动动作——这是省 token 的设计，不是坏了。
- 模型偶尔返回 `none` 是正常结果：她看了一圈，觉得不需要动。

## 验证记录（0.5.0）

- 桥接直连：`POST /pointer` 返回合法动作和人格化理由。
- 桌面实测一轮：截图 56 KB / 713 ms，模型往返约 12.2 秒，指针从副屏移到主屏指定位置。
- 关闭开关后浮层隐藏、观察停止；重新开启后从当前位置继续。
