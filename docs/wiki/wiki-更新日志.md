## 2026-11-18 · 0.3.6：点击通知打开聊天，不再跳到 “Electron”

| 变化 | 说明 |
| --- | --- |
| 现象 | 未聚焦时来消息会弹通知，点通知却打开一个叫「Electron」的窗口 |
| 根因 | toast 点击按 AUMID 启动开始菜单快捷方式；机器上有两个同 AUMID 快捷方式，其中 `Electron.lnk` 指向 `node_modules\electron\dist\electron.exe`，另一个指向便携版上次解压的临时目录 |
| 修复 | 启动时把 `MONOSABA DesktopPET.lnk` 修到当前运行的 exe（便携版用解压后的小 exe，点击约 1 秒；外层便携 exe 会重新解压 20 秒以上）并写入 AUMID；删除指向 `electron.exe` 的同 AUMID 遗留快捷方式；退出时指回外层 exe |
| 跳转 | 第二个实例转发回第一个实例时自动打开并聚焦聊天窗口 |
| 验证 | 从开始菜单快捷方式启动第二个实例，运行中的实例直接弹出聊天窗口 |
| 产物 | `MONOSABA-DesktopPET-0.3.6-portable.exe` |

## 2026-11-18 · 0.3.3：屏幕长时间没变化时暂停点评

| 变化 | 说明 |
| --- | --- |
| 问题 | 人离开电脑、待机动画 / 动态壁纸让画面“看起来在变”，点评仍会一轮轮重复 |
| 判断 | 每轮让希罗自己判断画面有没有实质变化；没变只回复隐藏标记 `[[SAME]]` |
| 暂停 | 连续 3 轮 `[[SAME]]` 后暂停，下一轮起不再调用模型；暂停时提示一次 |
| 恢复 | 每 30 秒检查：缩略指纹变化 > 约 20%，或鼠标移动 > 24px，就恢复 |
| 隐藏 | `[[SAME]]` 不显示在聊天、不写本地缓存，也不会生成气泡 |
| 全量检查 | 修复隐藏标记气泡、低速逐字输出失效、导入后失效预设 id、聊天字体颜色污染；清理未使用代码 |
| 产物 | `MONOSABA-DesktopPET-0.3.3-portable.exe` |

这里特意没有用“跳过 3 轮完全相同截图”的方案：Live2D 待机动作和动态壁纸会让像素一直变，固定阈值要么误停要么永远不停。改成让模型先做一次语义判断，只把真正“没变化”的轮次标记出来；恢复则用宽松的缩略指纹 + 鼠标移动，足够区分“人回来了”和“动画在动”。

## 2026-11-17 · 0.3.0：点评气泡改为主进程事件驱动

| 变化 | 说明 |
| --- | --- |
| 现象 | 聊天记录有点评，Live2D 旁边没有气泡 |
| 原因 | 气泡只认 `runCommentary` 返回值；聊天消息是轮询独立入库，回复慢 / 中途关开关时两边不同步 |
| 修复 | 主进程收齐一轮后广播 `chat:commentary`，桌宠只认这个事件；单轮最长等 3 分钟 |
| 保留 | 聊天窗口聚焦时仍暂停触发；关闭点评 / 切换人物仍清空气泡 |
| 产物 | `MONOSABA-DesktopPET-0.3.0-portable.exe` |

这不是「气泡被立刻隐藏」的问题，而是气泡和聊天记录走了两条链路：聊天记录由轮询写进本地 store，气泡等的是同一次 IPC 的返回。回复一慢，或用户在收齐前关掉点评，聊天已经有消息，气泡却永远不会出现。改成主进程收齐后主动广播，气泡就跟聊天记录对齐了。

点评和普通聊天的区别只在「触发方式」：它仍然走同一个 AstrBot 会话和多模态主模型，所以希罗会记得自己看过什么。桌面聊天里只留下她的回复，触发用的那句「随手瞥了一眼」不会出现。实现上最麻烦的是分段回复：AstrBot 一条回复可能拆成 3 次发送，间隔 2 秒左右，桌面端用 3.5 秒静默窗口把同一轮回复收齐，再截成最多 3 段、100 字放进气泡。

## 2026-11-16 · 0.2.6：修复升级后开机自启失效

| 变化 | 说明 |
| --- | --- |
| 现象 | 开过开机自启，更新版本后开机没有启动 |
| 根因 | 便携版 exe 带版本号，Run 注册表仍指向已删除的旧 exe |

## 2026-11-16 · 0.2.5：修复指令补全导致聊天窗口空白

| 变化 | 说明 |
| --- | --- |
| 现象 | 输入 `/` 后继续输入任意字符，窗口内容消失、任务栏按钮还在 |
| 根因 | `/commands` 里个别指令缺少 `aliases`，`filterCommands` 调用 `.some` 抛错，React 卸载整棵树 |
| 修复 | 指令数据统一归一化，过滤时再做数组判断 |
| 兜底 | 聊天窗口加错误边界，异常时显示「重新载入」 |
| 产物 | `MONOSABA-DesktopPET-0.2.5-portable.exe` |

这个 bug 之所以只在「`/` 之后再按一个键」时出现，是因为查询为 `/` 时所有指令名的 `startsWith("/")` 都为真，短路掉了 `aliases.some`；一旦变成 `/a`，就会走到缺失字段上。React 19 对渲染期未捕获异常的处理是卸载整棵树，所以窗口还在、内容全没了。

## 2026-11-16 · 0.2.4：聊天背景与透明度

| 变化 | 说明 |
| --- | --- |

| 面板背景不透明度 | 0–100 滑块，作用于标题栏 / 左栏 / 右侧面板 / 输入区 / 工具栏 / 状态栏，默认 92% |

| 拓展到全部 | 打开后背景图铺满整张卡片，主题暗层仍按两个滑块叠加 |

截图里最容易忽略的是「图片和暗层谁在上面」：CSS 的 `background-color` 画在 `background-image` 下面，直接把暗层写成背景色的话图片会把暗层盖住。这里改成两层 `background-image`——第一层是半透明的主题渐变，第二层才是照片，滚动容器里图片保持固定、消息在上面滚。

## 2026-11-16 · 0.2.3：发送流程修正

| 变化 | 说明 |
| --- | --- |
| 发送即上屏 | 点发送立刻清空输入框并插入半透明 pending 气泡，不再等 `/send` 响应 |
| 状态提示 | 请求中「消息正在发送…」→ 确认后「希罗正在回复中…」→ 超时「希罗没有回应。」 |
| 失败回滚 | 移除 pending 气泡，输入框为空时把原文放回 |
| 轮询对账 | 按文本认领 pending、按 id 去重，避免重复气泡和总数偏差 |
| 产物 | `MONOSABA-DesktopPET-0.2.3-portable.exe` |

原来的实现把「等待回复」和「发送请求」混成了一个状态：点发送就显示「希罗正在输入」，而草稿要等 `/send` 返回才清空。慢网络下（EasyTier）就会看到消息卡在输入框里、希罗却已经在“输入”。现在拆成两段：本地乐观上屏 + 发送中提示，桥接确认后才进入等待回复。

乐观消息的 id 用负时间戳；轮询如果先拿到真实消息，就按文本把它认领掉，`/send` 响应回来时再按 id 去重。失败时如果用户没有再输入，原文会放回输入框，避免白打一段字。

## 2026-11-16 · 0.2.2：任务栏图标最终修复

| 变化 | 说明 |
| --- | --- |
| 图标格式 | 窗口图标改用 `icon-chat.ico`，并显式 `win.setIcon()` |
| 任务栏身份 | 聊天窗口单独设置 AUMID `com.mengxj.monosaba.chat` |
| relaunch 图标 | `win.setAppDetails({ appIconPath, appIconIndex, … })` 指向聊天头像 |
| 产物 | `MONOSABA-DesktopPET-0.2.2-portable.exe` |

Windows 11 默认「合并任务栏按钮」，按钮显示的是 **AppUserModelID 的图标**，不是窗口自己的 `icon`。所以只改 `BrowserWindow.icon` 只能影响标题栏和 Alt+Tab；0.2.1 修好路径后任务栏仍然是进程默认图标。

这次的解法是给聊天窗口一个独立的 AppUserModelID，并把该身份的 relaunch 图标指向 ICO。`appIconPath` 必须是 `appId` 同时设置才会生效，`relaunchCommand` / `relaunchDisplayName` 也要成对出现。

| 修复 | 打包后任务栏图标变成默认图标 |
| 产物 | `MONOSABA-DesktopPET-0.2.1-portable.exe` |

根因不复杂但很典型：窗口 `icon` 写的是 `app.getAppPath()/build/icon.png`，开发模式指向项目根目录没问题；打包后 `app.getAppPath()` 是 `resources/app.asar`，而 electron-builder 的 `files` 只包含 `out/**` 和 `package.json`，`build/` 根本不在 asar 里。路径无效，Windows 就退回默认图标。

现在图标文件通过 `extraResources` 输出到 `resources/icon-chat.png`，主进程按 `app.isPackaged` 分别取 `process.resourcesPath` 和项目 `build/`。托盘图标和通知图标本来就走同一套解析，所以只有聊天窗口受影响。

### 桥接插件 0.3.1

| 修复 | 说明 |
| --- | --- |
| QQ 回复不同步 | AstrBot 重启后发送层捕获没有重新安装 |

两个都是「看代码觉得没问题、跑起来才暴露」的坑：

- aiocqhttp 的 `CQHttp.__getattr__` 会给**任何未知属性**返回一个可调用的 `functools.partial`，所以 `getattr(bot, "_desktoppet_capture_owner", None)` 永远不为 `None`。旧逻辑看到「标记已存在」就直接返回，重启后再也没有装过包装。现在改为判断「包装函数是否仍是当前 `bot.send_private_msg`」，并在收到消息、发起 LLM 请求前各补装一次；`/ping` 新增 `capture` 状态（`wrapped` / `task` / `captured` / `lastCaptureAt`）。
- AstrBot 的 `WakingCheckStage` 只要消息以 `wake_prefix` 开头就会删掉前缀，私聊也不例外。配置里有「希罗」且排在「希罗酱」前面时，`希罗酱…` 只被删掉「希罗」。桥接现在用原始消息组件重建 `message_str`，桌面和 QQ 两个方向都恢复完整文本，日志里会打印 `已恢复唤醒词截断`。

### 联调踩坑

- **聊天「桥接插件返回格式不正确」**：`/history` 带完整截图时响应接近 800KB，EasyTier 慢时半路截断。历史图片改为插件端压成最长边 480 / JPEG 75，超时 15s → 30s，客户端解析失败时记录原始响应。
- **选「屏幕 1」却截到屏幕 2**：这台机器 `desktopCapturer` 只枚举得到副屏，旧代码找不到目标屏时回退 `sources[0]`。改为只匹配 `display_id`，没有 source 就用 PowerShell + GDI `CopyFromScreen` 按屏幕序号截主屏。
- **缩略图消失**：增量轮询比 `/send` 响应先到，截图被当成重复消息跳过。改为合并进已有气泡。
- **面板一滑就消失**：自动轮换 / 穿透的小窗用 portal 渲染，不在「点外关闭」白名单和穿透命中并集里，补上引用即可。
- **强制顶层关掉后窗口掉底**：`setBounds` 会把窗口踢出置顶层。顺序改成「先改尺寸 → 声明 alwaysOnTop → moveTop」。
- **B 站客户端黑屏**：全屏透明覆盖层导致，`focusable:false` 只能缓解，最终没有继续修。
