# 希罗插件交接汇总（AstrBot 侧）

> 内部开发交接文档，不是网站发布稿。  
> 面向继续开发 MONOSABA DesktopPET / 其他 AstrBot 功能、需要与希罗五个核心插件联动的开发者。  
> 最后核对：**2026-11-18**；线上 AstrBot **4.29.1**；容器 `astrbot`。

---

## 0. 先看这里

1. **AstrBot 是唯一大脑**：人格、模型、记忆、心情、好感、睡眠、生活、日记都在 AstrBot。桌面端、网站、CLI 只是通道。
2. **主私聊是唯一主状态**：`Hiro:FriendMessage:1955272576`。好感、睡眠、生活、日记、人物画像只属于主私聊。
3. **群聊/访客严格隔离**：群聊只保留本群自己的 `/心情`；`/睡眠`、`/生活`、`/好感`、`/diary`、`/记忆` 在非主私聊直接拒绝。网站/未来桌面聊天按访客处理，使用独立记忆域和独立心情。
4. **五个核心插件**：`memory`（记忆/画像）、`mood`（心情/好感）、`sleep`（作息）、`life`（生活事件）、`diary`（日记）。
5. **读状态优先用公共方法**，不要直接读主私聊的 `mood.json` 会话；**写状态优先用插件 API/命令**，不要运行中直接改缓存型 JSON。
6. **暂不合并插件**：2026-11-18 已确认保留 `mood / sleep / life / diary` 四个独立插件，先固化隔离守卫和测试。

## 2. 会话模型（最重要）

### 2.1 UMO

AstrBot 的会话键是 `platform:message_type:session_id`。

| 通道 | UMO 形如 | 说明 |
|---|---|---|
| QQ 主私聊 | `Hiro:FriendMessage:1955272576` | **唯一主状态**；好感/睡眠/生活/日记/画像只认它 |
| QQ 群聊 | `Hiro:GroupMessage:<sender_id>_<group_id>` | `unique_session` 开启时是「发送者_群号」；关闭时是群号 |
| QQ 其他私聊 | `Hiro:FriendMessage:<qq>` | 独立会话；主私聊专属命令拒绝 |
| 网站访客 | `webchat:FriendMessage:webchat!site-<user>!<sid>` | 独立访客域；不映射到主私聊 |
| 桌面桥接 | `Hiro:FriendMessage:1955272576` | 桌面端故意共用主私聊；只适用于主人工具 |

> 群聊 UMO 不是简单的「群号」。当前线上 `unique_session=true`，实际是 `<sender_id>_<group_id>`。  
> 记忆插件 `_scope_of()` 对群聊取第一段生成 `group<sender_id>`，所以即使以后给群聊开记忆，也是「群内每个发送者各自一份」，不是群共享一份。

### 2.2 记忆域（scope）

| UMO | scope | 默认是否记录 | 备注 |
|---|---|---|---|
| `Hiro:FriendMessage:1955272576` | `qq1955272576` | 是 | 主记忆域 |
| `Hiro:FriendMessage:<其他QQ>` | `qq<其他QQ>` | 取决于 `channel_allowlist` | 主私聊专属数据不共享 |
| `Hiro:GroupMessage:<sender>_<group>` | `group<sender>` | **否** | 默认 `channel_allowlist` 不含群聊 |
| `webchat:...site-<user>...` | `site-<user>` | 是 | 访客自己的记忆 |
| 日记专用 | `diary` | 是 | 只允许主私聊检索 |

`channel_allowlist` 默认：

```text
Hiro:FriendMessage:1955272576,webchat
```

判断逻辑是 `umo.startswith(p) or p in umo`。**不要写太宽的 prefix**（例如只写 `Hiro` 会把所有 QQ 会话都放进来）。

### 2.3 数据归属

| 数据 | 归属插件 | 主私聊 | 群聊 | 网站访客 | 是否注入 |
|---|---|---|---|---|---|
| 八种情绪 | `mood` | 有 | 各自一份 | 各自一份 | 当前会话注入 |
| 好感/伴侣/分手 | `mood` | 有 | **无** | **无** | 只主私聊注入 |
| 睡眠状态 | `sleep` | 有 | **无** | **无** | 只主私聊注入/拦截 |
| 生活事件 | `life` | 有 | **无** | **无** | 只主私聊注入 |
| 日记 | `diary` | 有 | **无** | **无** | 不注入；可被主私聊记忆读取 |
| 长期记忆 | `memory` | `qq1955272576` | 默认不记 | `site-*` | 按当前 scope 检索 |
| 人物画像 | `memory` | 有 | **无** | **无** | 只主私聊 system prompt |

## 3. 插件契约

### 3.1 记忆 `astrbot_plugin_hiro_memory` 0.3.4

**钩子**

| 钩子 | 作用 |
|---|---|
| `on_llm_response()` | 抓一轮对话写入 `buffer/<umo>.jsonl`，攒够轮数/空闲后蒸馏 |
| `on_llm_request()` | 上下文压缩 + 按当前 scope 检索 + 注入临时记忆块；主私聊额外注入画像 |

**公共方法**

| 方法 | 说明 |
|---|---|
| `async run_backfill(*, since=None, include_diary=True) -> dict` | 从 `data_v4.db` 回填历史；重操作，只从管理入口调 |
| `async rebuild_all() -> int` | 清空并重建本插件知识库索引；重操作 |

> 记忆没有「add_memory」这种稳定公共 API。外部写入推荐走 JSONL + `reindex` 标记（见 §5.7）。

**数据**

```text
/AstrBot/data/plugin_data/astrbot_plugin_hiro_memory/
├─ buffer/<umo>.jsonl          # 未蒸馏对话
├─ memory/YYYY-MM-DD.jsonl     # 权威记忆
├─ profile.md                  # 人物画像（≤600 字）
├─ profile_core.md             # 跨年锚点（imp5 摘要）
├─ state.json                  # 文档 id、归档、预算、熔断
├─ reindex/                    # 外部改/删记忆后的重建标记
└─ logs/retrieval.jsonl        # 影子模式/召回观察
```

记忆条目：

```json
{"date":"2026-11-18","kind":"事件","imp":3,"text":"……","scope":"qq1955272576"}
```

- `kind`：`事实 / 事件 / 偏好 / 情绪 / 约定 / 关系 / 画像 / 日记`
- `imp`：1–5
- `scope`：**必须写**；缺 scope 的条目不会被 `entries_of_day(day, scope)` 选中

**检索隔离**

- `_rank()` 只保留当前 `scope`；主私聊额外允许 `diary`。
- 群聊/访客不能召回主私聊或 `diary`。
- 画像 `profile.md` / `profile_core.md` 只从 `primary_scope` + `diary` 生成，只注入 `admin_umo`。

**命令**

| 命令 | 说明 |
|---|---|
| `/记忆 状态` | 知识库、条目、缓冲、占用 |
| `/记忆 检索 <词>` | 手动检索 |
| `/记忆 刷新` | 立即蒸馏当前会话缓冲 |
| `/记忆 画像` | 立即重建画像 |
| `/记忆 回填 [YYYY-MM-DD]` | 从 DB 回填 |
| `/记忆 删除 <YYYY-MM-DD>` | 删除某天记忆 + 索引 |
| `/记忆 重建` | 重建全部索引 |

仅管理员，且只在主私聊 `admin_umo`。

### 3.2 心情 `astrbot_plugin_hiro_mood` 1.4.9

**钩子**

| 钩子 | 作用 |
|---|---|
| `on_llm_request()` | 注入当前会话心情块 + 主私聊好感态度块；主私聊处理表白/分手/冷战 |

**公共方法**

| 方法 | 签名 | 主私聊 | 群聊/访客 |

| `get_affection` | `(umo) -> dict` | 好感状态 | **`{}`** |
| `is_cold_war` | `(umo) -> bool` | 当前会话 | 当前会话自己的冷战 |
| `set_emotion` | `async (umo, name, value, reason="", *, pinned=False)` | 设置情绪 | 设置当前会话情绪 |
| `apply_external` | `async (umo, updates, reason="", *, write_memory=False)` | 批量调整 | 批量调整当前会话 |
| `start_cold_war` | `async (umo, reason="")` | 进入冷战 | 当前会话 |
| `end_cold_war` | `async (umo, reason="")` | 解除冷战 | 当前会话 |

### 3.4 生活 `astrbot_plugin_life` 0.1.8

**钩子**

|---|---|
| `on_llm_request()` | 只对 `target_umo` 注入“今天已经发生、他可能还不知道”的生活背景 |

目前**没有稳定的公共读取 API**。不要依赖 `_build_inject_block()` / `_status_text()` 这类私有方法。

**联动**

- 睡眠插件在睡前 N 分钟调用 `share_for_date()` 提前写+发；
- 起床后调用 `share_pending()` 补发；
- 日记插件在夜间休息时只写不发；
- 日记素材来自主私聊会话历史；群聊/访客不生成主日记。

## 4. 联动矩阵

| 方向 | 调用 | UMO | 说明 |
|---|---|---|---|
| `sleep` → `mood` | `get_affection(umo)` | 主私聊 | 晚安/早安门槛、分手挽回期 |
| `sleep` → `mood` | `is_cold_war(umo)` | 主私聊 | 冷战时不回 `zzZ`、不主动问候 |
| `sleep` → `mood` | `set_emotion(umo, "累", value, reason)` | 主私聊 | 被吵醒/起床后的累 |
| `life` → `mood` | `get_affection(target_umo)` | 主私聊 | 分享配额、噩梦最低好感、语气边界 |
| `life` → `mood` | `is_cold_war(target_umo)` | 主私聊 | 冷战暂停分享 |
| `life` → `mood` | `apply_external(target_umo, updates, reason=...)` | 主私聊 | 生活事件驱动情绪 |
| `life` → `sleep` | `begin_nightmare/end_nightmare(target_umo)` | 主私聊 | 噩梦惊醒/回睡 |
| `diary` → `sleep` | `is_night_rest(umo)` | 主私聊 | 夜间只写不发 |
| `sleep` → `diary` | `get_share_time()` / `share_for_date()` / `share_pending()` | 主私聊 | 睡前分享、起床补发 |
| `mood` → `memory` | 直接追加 JSONL | 主私聊 `memory_scope` | 强情绪/关系事件写长期记忆 |
| `memory` → `diary` | 读 `diary` 域 | 主私聊 | 画像/检索可包含日记 |
| 桌面桥接 → `mood` | 直接读 `mood.json` | 主私聊 | `/status` 计算衰减后的好感/情绪 |
| 桌面桥接 → AstrBot | 合成 `AiocqhttpMessageEvent` | 主私聊 | 走完整管线，记忆/心情/生活/日记都生效 |

## 5. 接入配方

### 5.1 安全获取插件对象

AstrBot 的 `get_registered_star()` 在启动早期可能返回 `None`，插件也可能被禁用。统一 fail-open：

```python
def get_plugin(context, name: str):
    try:
        star = context.get_registered_star(name)
        return getattr(star, "star_cls", None) if star else None
    except Exception:
        return None
```

使用：

```python
mood = get_plugin(self.context, "astrbot_plugin_hiro_mood")
if mood is None:
    return  # 或使用默认值
```

### 5.2 读心情 / 好感

```python
umo = event.unified_msg_origin

mood = get_plugin(self.context, "astrbot_plugin_hiro_mood")
emotions = mood.get_snapshot(umo) if mood else {}
affection = mood.get_affection(umo) if mood else {}
cold_war = mood.is_cold_war(umo) if mood else False
block = mood.get_block(umo) if mood else ""
```

- `get_snapshot(umo)`：当前会话自己的情绪，群聊/访客也能读自己的。
- `get_affection(umo)`：**只有主私聊有值**，其他会话返回 `{}`。
- `get_block(umo)`：当前会话心情块；主私聊额外带好感态度。会创建空 session，只读统计优先用前两个。

### 5.3 改心情

```python
mood = get_plugin(self.context, "astrbot_plugin_hiro_mood")
if mood:
    # 绝对强度
    await mood.set_emotion(umo, "累", 0.8, "被吵醒")

    # 批量增减
    await mood.apply_external(
        umo,
        [
            {"emotion": "开心", "delta": 0.2, "reason": "……"},
            {"emotion": "担心", "delta": -0.3, "reason": "……"},
        ],
        reason="生活事件",
        write_memory=False,
    )
```

- 两个方法都按 UMO 写当前会话，不会碰主私聊好感。
- `write_memory=False` 默认不写长期记忆；需要写时确认 UMO 是主私聊。

### 5.4 读睡眠 / 噩梦

```python
sleep = get_plugin(self.context, "astrbot_plugin_hiro_sleep")

sleeping = sleep.is_sleeping(umo) if sleep else False
night_rest = sleep.is_night_rest(umo) if sleep else False
status = sleep.get_status(umo) if sleep else {}
```

- 非主私聊：`is_*` 全部 `False`，`get_status` 返回 `{}`。
- 主私聊 `status["status"]` 才是 `awake/delaying/sleeping/woken/nightmare`。

噩梦联动：

```python
if sleep and await sleep.begin_nightmare(umo):
    try:
        # 发 3–6 段噩梦消息
        ...
    finally:
        await sleep.end_nightmare(umo)
```

只有主私聊会成功；非主私聊 `begin_nightmare` 返回 `False`。

### 5.5 读生活

生活没有公共 getter，直接读当天 JSONL：

```python
import json
from pathlib import Path

path = Path("/AstrBot/data/plugin_data/astrbot_plugin_life/events") / f"{day}.jsonl"
rows = []
if path.is_file():
    for line in path.read_text(encoding="utf-8").splitlines():
        if not line.strip():
            continue
        item = json.loads(line)
        if item.get("privacy") == "secret":
            continue
        rows.append(item)
```

使用前至少过滤：

- `privacy != "secret"`
- `occurred_at <= now`
- `status in ("occurred", "shared")`（如果要“已经发生”）
- `memory.keep` / `imp` 只用于生活插件自己的记忆策略

> 不要直接改 `events/*.jsonl` 或 `state.json`；生活插件内存里有状态副本，运行中改文件可能被覆盖。

### 5.6 读 / 分享日记

读正文：

```python
from pathlib import Path

book = Path("/AstrBot/data/workspaces/Hiro_FriendMessage_1955272576/diary/日记本.md")
text = book.read_text(encoding="utf-8") if book.is_file() else ""
```

分享：

```python
from datetime import date

diary = get_plugin(self.context, "astrbot_plugin_diary")
if diary:
    await diary.share_for_date(date.today(), force=False)
    await diary.share_pending()
```

- `share_for_date` / `share_pending` 只对主私聊 `umo` 生效。
- 日记本只追加，不要整本重写；分卷后当前卷是 `日记本.md` / `日记本-2.md`。
- 群聊/访客不要读主日记。

### 5.7 写长期记忆

**优先**：让记忆插件从正常对话里蒸馏，不要外部硬写。

**外部事实/工具结果**：追加 JSONL，然后放 `reindex` 标记，让插件重建当天索引。

```python
import json, re, time
from datetime import date
from pathlib import Path

root = Path("/AstrBot/data/plugin_data/astrbot_plugin_hiro_memory")
day = date.today().isoformat()
scope = "qq1955272576"          # 只有主私聊事实才写这个
text = "（电脑）他……"           # 不要写密码/密钥/截图原文

entry = {
    "date": day,
    "kind": "事件",             # 事实/事件/偏好/情绪/约定/关系/画像/日记
    "imp": 3,                   # 1–5
    "text": text,
    "scope": scope,
}

memory_file = root / "memory" / f"{day}.jsonl"
memory_file.parent.mkdir(parents=True, exist_ok=True)
with memory_file.open("a", encoding="utf-8") as f:
    f.write(json.dumps(entry, ensure_ascii=False) + "\n")

safe_scope = re.sub(r"[^A-Za-z0-9_-]+", "-", scope)[:40] or "x"
marker_dir = root / "reindex"
marker_dir.mkdir(parents=True, exist_ok=True)
(marker_dir / f"{day}-{safe_scope}.json").write_text(
    json.dumps({"day": day, "scope": scope, "op": "external", "ts": int(time.time())}, ensure_ascii=False),
    encoding="utf-8",
)
```

规则：

- `scope` 必须写；缺 scope 不会被检索。
- **群聊/访客内容绝不能写进 `qq1955272576`**。
- 外部写入只写摘要，不写原始截图、窗口标题里的敏感信息、密码/令牌。
- 标记文件会被插件在下一次聊天请求前或空闲巡检时处理；处理完删除，不需要重启。
- 不要直接改知识库 `index.faiss` / `doc.db`。

### 5.8 主动发消息

```python
from astrbot.api.event import MessageChain
from astrbot.api.message_components import Plain

await self.context.send_message(
    umo,
    MessageChain(chain=[Plain("……")]),
)
```

- 主私聊专属内容只发主私聊 UMO。
- `send_message` 成功只代表 AstrBot/NapCat 接受，不保证 QQ 客户端一定收到。
- 分段回复由 AstrBot 配置决定；不要自己伪造 `send_private_msg`。

### 5.9 合成事件：走完整 AstrBot 管线

如果新功能需要“像用户发了一条消息”一样触发记忆/心情/生活/日记，不要直接调 `provider.text_chat()`。参考桌面桥接：

```python
import time
import uuid

from astrbot.api.message_components import Plain
from astrbot.core.platform.astrbot_message import AstrBotMessage, MessageMember
from astrbot.core.platform.message_type import MessageType
from astrbot.core.platform.sources.aiocqhttp.aiocqhttp_message_event import AiocqhttpMessageEvent

abm = AstrBotMessage()
abm.type = MessageType.FRIEND_MESSAGE
abm.self_id = self_id
abm.session_id = user_id
abm.message_id = f"feature-{uuid.uuid4().hex}"
abm.group = None
abm.sender = MessageMember(user_id=user_id, nickname=nickname)
abm.message = [Plain(text=text)]
abm.message_str = text
abm.raw_message = None
abm.timestamp = int(time.time())

event = AiocqhttpMessageEvent(
    message_str=text,
    message_obj=abm,
    platform_meta=adapter.meta(),
    session_id=user_id,
    bot=bot,
)
event.role = "admin"                 # 仅主人工具；访客功能不要设 admin
event.set_extra("_feature_origin", "desktop")
adapter.commit_event(event)
```

- 主私聊 UMO 才会触发主好感/睡眠/生活/日记。
- 访客 UMO 只会写访客自己的记忆/心情；主私聊专属 API 会返回空/拒绝。
- 不要直接调 `provider.text_chat()`：会绕过 `on_llm_request` / `on_llm_response`，记忆、心情、生活、日记、沉浸插件全部失效。

### 5.10 跳过好感 / 评价

- `event.set_extra("mood_skip_affection", True)`：mood 1.4.9 / 1.5.0 会跳过本轮好感变化，但仍会评价情绪（1.5.0 推荐配合下面两个一起用）。
- `event.set_extra("mood_skip_appraisal", True)` 或 `mood_skip_all`：mood **1.5.0** 在 `on_llm_request` 和 `on_llm_response` 开头整轮跳过（不改心情、好感、冷战、记忆）。桌面桥接 **0.3.4** 三个标记都会设，所以屏幕点评完全不参与心情 / 好感。
- 睡眠：桥接 0.3.4 的 `/send?commentary=true` 会先查 sleep 插件；睡着时直接返回 `sleeping:true` / `reply:"zzZ"`，不注入回合、不截图、不计睡眠消息。`/status` 也返回 `sleeping` / `sleepStatus`。
- 睡眠 / 生活：sleep **0.1.4** / life **0.1.9** 的 `on_llm_request` 看到 `mood_skip_appraisal` 会提前返回，点评不更新 `last_user_at`、不计未回复、不触发拖睡 / 吵醒。

## 6. 新功能隔离检查清单

开发任何会读写希罗状态的功能，先过一遍：

- [ ] 这个功能是**主私聊专属**，还是群聊/访客也能用？
- [ ] 用了正确的 UMO，没有把主私聊 UMO 硬编码到访客路径？
- [ ] 命令是否同时检查 `event.is_admin()` 和 `event.unified_msg_origin == 主 UMO`？
- [ ] 公共读取方法对非主私聊是否返回空/False，而不是主数据？
- [ ] 有没有直接读 `mood.json` 的主会话？改成 `get_snapshot(umo)` / `get_affection(umo)`。
- [ ] 有没有把群聊/访客内容写进 `qq1955272576` 记忆？
- [ ] 有没有把 `profile.md` / 日记 / 生活 / 好感注入群聊或访客？
- [ ] 睡眠中 `zzZ` 会 `stop_event()`；新钩子是否接受“这一轮不会到模型”？
- [ ] 新功能写记忆时是否带 `scope` 和 `reindex` 标记？
- [ ] 是否在运行中直接改 `mood.json` / `sleep.json` / `life/state.json`？这些有内存副本，改文件后要重载/重启。
- [ ] 是否直接调 `provider.text_chat()`？改成走 AstrBot 管线。
- [ ] 主动消息是否只发主私聊，且内容不包含主私聊秘密到群聊？
- [ ] 失败是否 fail-open，不影响正常聊天？

## 7. 已知坑 / 当前不一致

### 7.1 `mood_skip_appraisal` 与 `mood_skip_affection`（2026-11-18 已修复）

- 旧问题：桌面桥接 0.3.3 只设 `mood_skip_appraisal`，mood 1.4.9 只读 `mood_skip_affection`，所以点评轮仍会评价心情并影响好感。
- 现在：mood **1.5.0** 在 `on_llm_request` / `on_llm_response` 开头识别 `mood_skip_appraisal` 与 `mood_skip_all`，整轮跳过；桥接 **0.3.4** 同时设 `mood_skip_appraisal` / `mood_skip_affection` / `mood_skip_all`。
- 新功能要跳过整轮：设 `mood_skip_appraisal=True`（或 `mood_skip_all=True`）；只跳过好感：`mood_skip_affection=True`。
- 验证：线上跑一轮真实点评，`/status` 的好感、今日增减、`updatedAt`、`thoughtAt`、心情原因均不变。

### 7.2 强情绪记忆没有 reindex 标记

`mood._write_memory()` 把强情绪写进 `memory/YYYY-MM-DD.jsonl`，但没有写 `reindex` 标记；关系事件 `_write_relation_memory()` 会写。  
所以强情绪记忆可能要等下一次 flush/夜间整合才进知识库。需要立刻可检索时，外部补一个 marker。

### 7.3 群聊记忆是「按发送者」不是「按群」

`memory._scope_of()` 对 `GroupMessage` 取 `session_id.split("_")[0]`。当前 `unique_session=true` 时第一段是发送者 QQ，所以 scope 是 `group<sender_id>`。  
默认群聊不记录；如果以后开启，请确认这是你要的粒度。

### 7.4 睡眠 `zzZ` 会截断后续钩子

睡眠中普通消息由 sleep 插件直接发 `zzZ` 并 `stop_event()`；其他插件的 `on_llm_request` 不会执行。新功能如果需要“睡着也记录/统计”，要在 `on_llm_response` 或消息入口层做，不能只依赖 `on_llm_request`。

### 7.5 直接改缓存型状态文件不安全

- `mood.json`、`sleep.json`、`life/state.json`、`diary/state.json` 在插件内存里有副本。
- 运行中直接改文件，可能被下一次 `_save_state()` 覆盖。
- 优先用公共方法或命令；必须改文件时，改完重载插件/重启容器。

### 7.6 记忆 JSONL 是权威，知识库是派生

- 改 JSONL 不会自动改知识库；要 `reindex` 标记或 `/记忆 重建`。
- 不要手改 `index.faiss` / `doc.db`。
- 删除/修改单条记忆后，必须让对应 `day/scope` 重建。

### 7.7 版本/日志

- 版本以 `metadata.yaml` 为准；`@register` 版本号已同步。
- 启动日志会打印 `Plugin astrbot_plugin_... (x.y.z)`；对不上就是没部署成功或没重启。
- 旧版 sleep 0.1.0 有群聊 `/睡眠` 泄漏主好感的问题；要求 >= 0.1.3。

## 11. 一句话总结

> 主私聊是唯一主状态；群聊只保留自己的心情；访客只写自己的记忆和心情。  
> 新功能读状态用公共方法，写状态用插件 API 或 JSONL + `reindex`；不要把主好感、主睡眠、主生活、主日记、主画像带到群聊或访客。  
> 需要“像用户发消息”时走 AstrBot 管线，不要直接调 `provider.text_chat()`。
