「仿 QQ」不是把界面画成 QQ，而是把**手机 QQ 的那段对话原样搬到桌面**：同一个人格、同一份记忆、同一个会话，桌面上发的话只回桌面，手机上发的消息实时同步进来，分段、表情包、指令和未读都按 QQ 的节奏走。

## 三种界面

| 形态 | 尺寸 | 特点 |
| --- | --- | --- |
| 小窗 | 420×600 | 贴在桌宠旁边，始终置顶、不占任务栏，只显示最近 40 条 |
| 完整版 | 1040×700 | 左窄栏 / 中间聊天 / 右侧状态面板，可拖边缘缩放，进入任务栏 |
| 日记 / 记忆 | 独立窗口 | 与聊天互不影响，可正常抢焦点 |

小窗卡片按「桌面透出 15%」实现（85% 不透明度），完整版只有消息区 60% 不透明度，标题栏、左栏、输入区和状态面板保持高不透明度。透明窗口不能系统缩放，完整版用自绘的 8 向热区，由主进程采样光标位置。

完整版是 QQ 式布局：头像、时间、日期分隔、连续消息分组（同一角色 3 分钟内合并）、未读数和底部状态栏。右侧状态面板实时显示好感度、今日增减、八种心情强度、冷战 / 伴侣、最近心里话和最近对话，新消息后 3 秒缓存刷新。

## 两套消息通路

```
桌面发消息
  聊天窗口 → chat:send → ChatService.send
            → POST /send {text, image?}
            → 桥接构造 AstrBotMessage + 假 bot（_DesktopBot）
            → AstrBot 管线 → 回复只走假 bot → 写回桌面日志
            → 真实 QQ 不受影响

手机发消息
  QQ → NapCat → AstrBot 管线 → 正式回复 send_private_msg
                                 ├─ 真的发到手机
                                 └─ 被桥接包装，解析 OneBot 消息段写入日志
  桌面 700ms 轮询 /messages?after=<cursor> → 增量气泡
```

关键点：

- 桌面事件的 `bot` 是假 bot，所有 `send_private_msg` 都被吞掉并记录成 `origin="desktop"`，所以桌面聊天不会污染 QQ。
- 手机方向的回复靠包装**真实** `send_private_msg`，发送成功后再记录；分段回复是多次发送，天然变成多个气泡。
- 两边共用 UMO `Hiro:FriendMessage:1955272576`，记忆、人格、上下文完全一致。

### 首次回填与增量

- 打开窗口先 `/bootstrap`：桥接返回全部可用日志（最多 2000 条）+ AstrBot 会话历史（最多 500 条）+ cursor + epoch。
- 历史没有时间戳，按「日志是历史的一段后缀」找最长匹配，只保留一份，再给历史部分按 1 分钟间隔倒推近似时间。
- 之后按 cursor 增量拉取，本地累积；`epoch` 变化视为桥接日志重置，清空 cursor 重新 bootstrap。
- 本地缓存默认 2 万条 / 500MB，超限删最旧；缩略图单独 200MB。

## 消息模型

```ts
type ChatMessage = {
  id: number;          // 桥接日志 id；历史/合成消息为负数或 0
  ts: number;
  role: "user" | "assistant";
  origin?: "qq" | "desktop" | null;
  text: string;
  image?: string | null;        // 旧接口内联截图
  attachments?: {               // 表情包 / 图片
    type: "image";
    media: string;              // 媒体 id，按需向 /media 取图
    mime: string;
    width?: number; height?: number;
    animated?: boolean; bytes?: number;
  }[];
  live?: boolean;      // 本次运行实时收到，保留 GIF 动画
  approximate?: boolean; // 历史回填的近似时间
};
```

图片不直接塞进消息，桌面只缓存缩略图（480px 内静态 WebP，GIF 取第一帧），点开原图时再向桥接 `/media` 请求 base64。实时消息的 GIF 用原图，历史消息用静态缩略图，兼顾流量和体验。

## 分段回复与表情包

AstrBot 的分段回复本来就是多次 `send_private_msg`，桥接逐条记录后，桌面按顺序渲染成多个气泡，不再拼成一条。配置在 AstrBot 侧（`platform_settings.segmented_reply`），桌面不做二次拆分。

- 纯图片 / 表情包且没有文字的消息按**贴纸**渲染：无气泡、最大 180px、靠边对齐。
- 文字 + 图片的消息仍然是一个气泡，图片在文字下方。
- 表情包插件（meme / meme_manager）绕过普通回复直接调 QQ 接口时，也会被发送层捕获，所以桌面能看到，手机上也会真的收到。

## 指令

输入 `/` 弹出补全：

- 指令列表来自桥接 `/commands`（动态读取 AstrBot 注册的指令与子指令），失败时用内置兜底；
- `↑↓` 选择、`Tab` 补全、`Enter` 发送；
- 桌面端放开全部指令，注入事件按 `role = "admin"` 处理；
- 危险指令（`/reset`、`/new`、`/心情 重置`、`/记忆 重建`、`/provider`、`/persona`、`/ni` 等）发送前二次确认，确认框里显示原文；
- 指令回复同样只回桌面。

## 获取屏幕

- 顶部「获取屏幕」开关，默认关，记住上次状态和多屏选择。
- 打开后每条桌面消息附带当前屏幕截图，最长边 1280、JPEG 85。
- 截图链路：`desktopCapturer` → 目标屏没有 source 时用 PowerShell + GDI `CopyFromScreen` 按屏幕序号截取。
- 带截图的消息会通过 `TextPart(...).mark_as_temp()` 临时注入「画面里的 Live2D 桌宠是希罗本人」，不写进会话历史。
- 截图失败仍然发送文字，并提示「截图失败，已只发送文字」。

## 个性化（0.2.0）

| 功能 | 说明 |
| --- | --- |
| 左栏「我」 | 希罗 / 我两个条目，右键打开资料菜单 |
| 头像 | 上传 / 拖入、拖动平移、滚轮缩放、历史头像回选，输出 256×256 PNG |
| 名称 | 1–16 字，只改本机显示 |
| 主题 | 日间 / 夜间 + 任意主题色，CSS 变量 + `color-mix()` |
| 预设 | 日/夜 + 颜色命名保存，默认「希罗」＝夜间红黑 |
| 字号 / 行距 | 小 / 中 / 大；紧凑 / 标准 / 宽松 |
| 背景 | 聊天区 / 面板两个不透明度滑块；可上传自定义背景，支持「拓展到全部」 |
| 随机点评 | 开关 + 最短 / 最长间隔（最小 30 秒，可填更大值）；截前台全屏所在屏，否则取鼠标屏；气泡常驻最多 3 轮、不通知、不影响心情；与 Live2D 控制面板同步 |
| 设置 | 通知、置顶、开机自启、存储信息与迁移、版本诊断 |

主题只作用于聊天窗口，桌宠气泡和 Live2D 控制面板保持原来的主题令牌。夜间沿用原红黑观感，日间是暖白底 + 深色字。

随机点评的设置也放在聊天设置里，但它属于桌宠能力：真正执行的是桌宠渲染层的计时器，聊天窗口只负责读写同一份 `config.commentary`。开启后点评会显示在桌宠气泡里，不会插进聊天列表；只有希罗的回复会像普通聊天一样出现在会话中。

## 稳定性：跑起来才会遇到的坑

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| AstrBot 重启后 QQ 回复不再同步 | `CQHttp.__getattr__` 把未知属性伪装成可调用的 `partial`，`getattr` 永远不为 `None`，旧逻辑误判「已安装」 | 改为判断包装函数身份，每 3 秒自检并在收消息 / LLM 请求前补装 |
| 「希罗酱…」变成「酱…」 | `WakingCheckStage` 无条件剥掉 `wake_prefix` | 用消息组件重建 `message_str` |
| 「桥接插件返回格式不正确」 | `/history` 带完整截图接近 800KB，慢网络下截断 | 历史图片压到 480px / JPEG 75，超时 30s，记录原始响应 |
| 选屏幕 1 截到屏幕 2 | `desktopCapturer` 只枚举到副屏，回退 `sources[0]` | 只匹配 `display_id`，否则 GDI 兜底 |
| 截图缩略图消失 | 轮询比 `/send` 响应先到，截图被当重复消息 | 合并进已有气泡 |
| 完整版消息区不是 60% | 透明窗口的 `background` 被内层覆盖 | 把透明度放到消息区自身 |
| 小窗在浅色桌面像全透明 | 深色半透明卡片对比不足 | 调整为 85% 不透明度并加背板模糊 |

## 关键接口

| 接口 | 用途 |
| --- | --- |
| `GET /ping` | 平台 / QQ 状态、版本、`capture` 自检 |
| `GET /bootstrap` | 首次全量：日志 + 会话历史 + cursor + epoch |
| `GET /messages?after=` | 增量消息，带 `hasMore` |
| `POST /send` | 桌面消息注入（文字 + 可选截图） |
| `GET /history` | 旧版历史接口（保留兼容，带图片缩略图） |
| `GET /status` | 心情 / 好感面板数据 |
| `GET /media` | 原图 / 缩略图 base64 |
| `GET /commands` | AstrBot 指令树 |

桌面侧 IPC 统一走 `chat:*`：`initial`、`load-more`、`send`、`media`、`commands`、`status-data`、`set-mode`、`set-pinned`、`set-notifications`、`mark-read`、`profile-*`、`set-theme`、`set-font-scale`、`set-line-height`、`storage-*`、`diagnostics`。

## 还可以往哪走

- **实时读屏**：现在只在手动开启时截一次图。下一步可以做「最新帧缓存 + 临时图片 part / `look_screen` 工具 + WebSocket 推送」，让希罗每 5–10 秒自己看一眼屏幕，而不是每条消息都塞图。
- **共同游戏**：在实时读屏之上加一个「第二个鼠标」的操控通道，先做简单互动（指位置、切窗口），再考虑输入模拟。
- **多角色会话**：左栏现在固定希罗 + 我，之后可以扩成联系人列表，每个角色独立的 UMO 和记忆。
