MONOSABA DesktopPET 是把网站里的希罗 / 艾玛 Live2D 看板娘搬到 Windows 桌面的独立程序。它不是一个缩小版网页，而是三层结构：**全屏透明覆盖层负责人物与桌面交互，本地主进程负责窗口 / 配置 / 存储，AstrBot 桥接插件负责和手机 QQ 共用同一个会话**。

当前桌面版本 **0.5.0**，服务器桥接插件 **0.4.1**，心情插件 **1.5.0**，睡眠插件 **0.1.4**，生活插件 **0.1.9**，记忆插件 **0.3.5**。

## 为什么是全屏透明覆盖层

网页版的布局、气泡、控制面板、拖拽和视线跟随都依赖「整个视口都是人物的画布」，改成小窗口会推翻全部布局。所以桌宠直接铺满所在屏幕的工作区：

- 无边框、透明、置顶、不占任务栏；
- 窗口 `focusable: false`（Windows 下对应 `WS_EX_NOACTIVATE`），点击、拖拽、滚轮都响应，但不会把前台窗口切走；
- 需要点击穿透时用 `setIgnoreMouseEvents(true, { forward: true })`，只把人物实际 alpha 区域、齿轮、面板和小窗「接管」回来；
- 命中判定放在渲染层用 `mousemove` 的 `clientX/clientY` 做，避免缩放屏下主进程坐标和渲染坐标错位。

**已知限制**：全屏覆盖层会让部分播放器（典型是 B 站桌面客户端）在黑屏检测上误判。`focusable: false` 只能缓解，不能彻底解决；最终没有继续修。

## 技术栈

| 层 | 选型 |
| --- | --- |
| 壳 | Electron 45 + electron-vite 6 |
| 渲染 | React 19 + TypeScript |
| Live2D | PixiJS 8 + `untitled-pixi-live2d-engine` + Cubism 5 |
| 打包 | electron-builder，Windows x64 便携版 |
| 服务端 | AstrBot 4.29 + 自写桥接插件 + NapCat（OneBot v11） |

不使用 Next.js、数据库和前端路由：桌宠是单页多视图（人物视图 / 聊天视图 / 日记窗口），路由成本高于收益。

## 进程与视图

```
main
 ├─ window.ts            全屏透明覆盖层、置顶、屏幕切换、强制顶层
 ├─ mouse-passthrough.ts 原生鼠标穿透 + 渲染层命中并集
 ├─ cursor-hit-test.ts   按人物 alpha / 控件矩形决定是否接管鼠标
 ├─ tray.ts              托盘菜单、未读红点图标
 ├─ config.ts            %APPDATA%\monosaba-desktoppet\config.json
 ├─ auto-launch.ts       开机自启（当前用户登录计划任务 + Run 项兜底）
 ├─ diary/               系统 OpenSSH 读日记与记忆（ssh2 在 Electron 主进程会卡死，弃用）
 ├─ chat/                聊天服务、桥接客户端、截图、缓存、媒体、设置导入导出
 ├─ profile.ts           本机资料：显示名 + 头像 + 历史头像
 ├─ commentary.ts        随机点评：选屏、截图、模型判断画面是否变化、暂停 / 恢复
 ├─ commentary-marker.ts 点评的隐藏 [[SAME]] 标记识别
 ├─ diary-window.ts      独立可聚焦日记窗口
 ├─ pointer-window.ts    第二指针浮层：每块屏一个透明置顶窗口、坐标路由
 ├─ pointer-ai.ts        指针观察：定时截图、指纹比对、调用模型、下发动作
 └─ chat-window.ts       小窗 / 完整版聊天窗口与全部 chat:* IPC

preload
 └─ contextBridge 暴露 window.petApi（人物、日记、聊天、资料、主题、存储、指针）

renderer
 ├─ 人物视图（全屏透明）
 ├─ 聊天视图 ?view=chat
 ├─ 日记视图 ?view=diary
 ├─ 指针视图 ?view=pointer
 └─ lib/pointer/ani.ts   .ani 光标解码（RIFF → ICO → RGBA 帧）
```

聊天窗口和日记窗口都是独立的 `BrowserWindow`，与人物覆盖层分开：人物层永远不可聚焦，聊天 / 日记需要键盘输入时可以正常抢焦点。

## 人物与桌面交互

- **点击**：随机表情 + 气泡；艾玛有 75% 概率播放点击音效（冷却 1 秒）。
- **拖拽**：左键按住 ≥0.5 秒且位移 >4px，或直接中键拖动；位置写入 localStorage。
- **缩放**：控制面板滑杆 10%–300%，与位置一起持久化。
- **控制面板布局**：显示人物 / 鼠标穿透 → 开机自启 / 自动轮换 → 强制顶层（整行）→ 真实交互（随机点评 + 希罗指针，同一行等宽）→ 显示屏幕 → 人物大小。「真实交互」只对希罗显示；「希罗指针」是独立总开关（默认开），点击开关，悬停打开小窗：总开关、闲时随机移动、大小（1.0–4.0×，默认 1.5×）、观察间隔（1–30 秒，默认 10）、状态行和「立即观察一次」。面板高度用 `ResizeObserver` 实测，新增区域后自动避让屏幕边界。
- **第二指针（希罗指针）**：Windows 只支持一个系统光标，所以第二指针是独立浮层绘制的：每块屏一个全屏透明、置顶、鼠标穿透的窗口，作为桌宠窗口的 owned window 压在人物上面。皮肤 `Normal.ani`（12 帧 32×32、约 12fps）在渲染层解码；默认 1.5×，放大用像素对齐不发虚。没有 AI 操控时自己按原来的随机视线节奏游走；Live2D 视线只跟它，真实鼠标移动不再影响视线。小窗里可以关掉「闲时随机移动」：指针停在原地只等 AI，人物闲时仍然自己随机看。浮层出现时 Windows 会清掉主窗口的置顶，所以「强制顶层」循环和浮层创建 / 切屏时会补回 `setAlwaysOnTop`。
- **AI 指针观察**：开关打开后每 N 秒截一张压缩小图（长边 768 / JPEG 70），先用 32×18 灰度指纹和上一轮比较，画面明显变化或换屏才调用模型；画面不动时 0 token。选屏与点评一致（前台全屏屏优先，否则鼠标所在屏）。桥接 `/pointer` 用当前人格直连 `text_chat`，带最近 6 条对话摘要，模型返回「动到哪 / 不动」、0~1 的相对坐标和一句闲聊；桌面端映射到 DIP、缓动过去、停留后再交回游走。只移动，不点击；睡着不观察，每天最多 500 次。关掉指针 = 隐藏浮层 + 停止观察。
- **聊天即指令**：桌面每发一条消息，指针约 1.2 秒后立刻观察一次，不等 10 秒周期；用户原话作为 `hint` 直接交给模型，明确让它指哪里就照做。每次移动她还会随口说一句，作为同一人格的聊天消息出现；这些消息不进 AstrBot 历史、不增加未读、不弹通知，下次聊天时再临时告诉聊天人格「你刚才说过什么」。
- **双击右下角图标**：打开聊天（240ms 判定，单击仍然是控制面板，艾玛不接入聊天）。
- **屏幕切换**：按坐标排序编号「屏幕 1 / 屏幕 2 / …」，主屏标注；托盘也有兜底入口。
- **强制顶层**：开启后窗口扩展到整屏（含任务栏）并压在置顶层最前；关闭时先改尺寸、再声明 `alwaysOnTop`、最后 `moveTop`，否则窗口会掉到最底层。
- **自动轮换**：5–600 秒区间随机，悬停滑杆设置；人物隐藏或面板打开时暂停。
- **随机点评**：30 秒起、不设实际上限的随机间隔（默认 30–300 秒），到点截取**当前活跃屏幕**——前台全屏 / 最大化窗口所在屏优先，没有则取鼠标所在屏——让希罗用 10~100 字、1~3 段点评。点评按轮次显示在人物旁边：每轮独立一条气泡，底边贴人物头顶向上生长，超出屏幕时从顶部渐隐；最多保留设置的轮数（默认 3），普通短气泡临时盖住后恢复。字号（8–64px）、背景不透明度、位置（正上方 / 左侧 / 右侧 / 自动）、最大宽度、纯文字、首行缩进、字体都在聊天设置里。开启后连续 3 轮希罗判断画面没有实质变化（回复隐藏标记 `[[SAME]]`）就暂停，暂停后每 30 秒用宽松缩略指纹 + 鼠标移动判断是否恢复。关闭点评或切换人物清空，重启不恢复。点评不增加未读、不弹通知，也不参与心情 / 好感评估（桥接 0.3.4 + mood 1.5.0 整轮跳过）；睡着时只回 `zzZ`，不截图、不调用模型。人物隐藏或面板打开时暂停；聊天窗口只在**聚焦且 2 分钟内有输入 / 发送**时让路，窗口开着但没人理不影响。设置 →「随机点评」显示下次时间、上次结果和截图耗时，并可「立即点评一次」；每次尝试写入 `logs/commentary.log`，不会再出现“开了却一直不触发”却无从排查的情况。
- **悬停变淡**：常态 / 悬停两档不透明度，开启穿透后鼠标移到人物上 0.3 秒渐变，移开 0.2 秒恢复。
- **面板主题**：根节点 `data-pet-character="hiro|ema"` 切换黑红 / 白粉两套令牌，面板尺寸和布局不变，只换颜色。

## 日记与记忆

日记和记忆不经过网站 API，直接用系统 OpenSSH 读服务器上的文件：

```
ssh <user>@<host> "cat …/diary/<date>.json"
ssh <user>@<host> "cat …/memory/*.jsonl"
```

- 独立小窗口，右上角最小化 / 关闭；保留网页版咒语 `hiro110`，输错会提示正确密钥。
- 「重新载入」是左下角红色环形刷新图标，「合上日记」是左下角折纸角 + 纸张色 ✖。
- 记忆入口在右下角，平时隐藏、悬停渐显；切到记忆页时用 `capturePage` 做 16px 方块的马赛克溶解。
- 「篡改记忆の魔法」：华文行楷红字入口，开启后 64px 钢笔光标；选中一条可改正文，其余内容被黑色为主的随机马赛克遮罩并轻微抽搐。写入走 SSH + `docker exec`，改完触发记忆插件重建当天索引。

## 聊天与 QQ 互通

这是整个项目最复杂的部分，单独成篇：**《仿QQ聊天终端》**。这里只放总体拓扑：

```
桌面聊天窗口 ──HTTP(Bearer)──▶ astrbot_plugin_desktoppet_bridge
      ▲                              │
      │  /bootstrap /messages        │ 注入 AstrBotMessage（假 bot，只回桌面）
      │  /send /status /media        ▼
      └────────────────────────  AstrBot 会话（UMO: Hiro:FriendMessage:1955272576）
                                     │
                                     ├─ 正式回复 → NapCat → 手机 QQ
                                     └─ 发送层被插件包装 → 写入桌面日志
```

关键约束：

- 桌面消息**只回桌面**，不投递到 QQ；手机 QQ 的消息靠桥接插件在发送层逐条记录，桌面增量轮询。
- 会话、人格、长期记忆与手机 QQ 完全共用，所以桌面和手机看到的是同一个希罗。
- 随机点评也走同一个会话：触发消息带 `〔桌面屏幕点评〕` 标记，桥接不把它写进桌面日志、不落盘截图；`/bootstrap` / `/history` 返回桌面时过滤该标记，所以桌面聊天只看到希罗的点评回复，但上下文和记忆里保留了完整回合。
- 桥接需要 `plugin` scope 的 API Key；Key 只在本地配置和服务器数据库里。
- **撤回**：每条桌面消息带一个回合 id；发送后、回复落地前可以在桌面上撤回。桥接会中止正在跑的 Agent（AstrBot 的 `agent_stop_requested`）、丢弃这一轮的回复、删掉桥接日志，再把会话历史里刚写入的「user + Stop output. + Output stopped.」裁掉，让心情 / 记忆整轮跳过。下一轮她看不到这条消息。
- **引用**：右键消息可以引用（自己或希罗的都行）。发给她的文本会带 `〔引用希罗的消息〕> 摘要` / `〔我的回复〕` 前缀；桌面气泡只显示引用块，点击跳回原消息。
- **指针**：指针开着时桌面消息会带 `pointerEnabled`，桥接用临时 `TextPart` 注入 `pointer_hint`（不写进历史），让她知道自己拥有第二指针；`/pointer` 是独立的一次性观察接口，不经过 Agent，所以不会污染会话、记忆和心情。

## 本地存储

| 数据 | 位置 |
| --- | --- |
| 配置 | `%APPDATA%\monosaba-desktoppet\config.json` |
| 聊天记录 | 默认 `%APPDATA%\monosaba-desktoppet\chat-cache\`（可迁移） |
| 缩略图 | 同目录 `thumbs/` |
| 本机资料 | `%APPDATA%\monosaba-desktoppet\profile\profile.json` |
| 自定义头像 | 同目录 `avatars\<角色>\<id>.png`，每角色保留 12 张 |
| 人物位置 / 缩放 / 开关 | 渲染层 localStorage |

聊天记录支持在设置里改到任意可写目录：先复制 `messages.jsonl`、`meta.json`、`thumbs/` 到新目录再切换，旧目录保留为备份；目标目录已有聊天记录会拒绝，失败不动原数据。

聊天个性化设置可以导出 / 导入本地 JSON（数据与存储 → 备份与恢复）：只包含主题与色彩预设、背景透明度、桌宠气泡、两套字体、逐字输出、点评间隔和字体预设，不包含 API Key、服务器地址、缓存路径和聊天记录。导入按字段合并，失败不写配置。

## 构建与发布

```bash
npm install
npm run typecheck
npm run build          # electron-vite build
npm run build:win      # 产出 dist/MONOSABA-DesktopPET-<version>-portable.exe
```

- 默认人物决定 exe 图标：`VITE_DEFAULT_CHARACTER=ema` 使用 `build/icon-ema.ico`，否则用希罗 `build/icon.ico`。
- 便携版不写注册表，双击即用；首次启动会在 `%APPDATA%` 建配置目录，聊天记录与头像都在用户目录。
- 开机自启写当前用户的登录计划任务（`MONOSABA DesktopPET`，登录后延迟 12 秒，动作 `<便携 exe> --autostart`），计划任务不可用时回退 `HKCU\...\Run`；移动 exe 后需要重新开关一次。`--autostart` 的第二个实例只把桌宠带到前台，不弹聊天。启动 / 切换问题看 `logs\startup.log` 与 `logs\chat-window.log`。

## 已知限制

- 全屏透明覆盖层与个别播放器的黑屏检测冲突（B 站客户端），未能彻底解决。
- 人物窗口不可聚焦，控制面板里的键盘快捷键（Esc、方向键）不可用。
- 第二指针是绘制层，不是系统光标：全屏独占游戏、UAC 安全桌面看不到；虚拟桌面切换时跟随当前桌面；截图 / 随机点评会拍到它；待机时只走桌宠所在屏幕的活动区（任务栏那条不覆盖）。
- 第二指针目前只做待机游走和视线跟随，不能点击；以后 AI 接入需要点击 / 拖拽时会短暂借用系统光标（你的光标会闪一下）。
- 日记 / 记忆依赖 EasyTier + 本机 OpenSSH；外部机器没有网络时只能看到「啥也没写」。
- 桥接插件的发送层捕获依赖 AstrBot 内部结构，升级大版本后需要回归 `/ping` 的 `capture.wrapped`。
